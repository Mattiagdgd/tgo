# iOS Anonymous Bluetooth Chat

This SwiftUI sample outlines an anonymous Bluetooth chat client that targets iOS 12 and later. It demonstrates:

- User registration with a locally stored display name.
- Bluetooth LE discovery and advertising of peers.
- Chat rooms with optional password protection backed by a simple keychain helper.

## Project setup

1. Open Xcode 14 or later.
2. Create a new **App** project named `BluetoothChat` using the SwiftUI interface template.
3. When the project loads, delete the autogenerated Swift source files inside the project target.
4. Drag the Swift files inside `mobile/ios/Sources` into the project navigator. Ensure they are added to the main application target.
5. Add the `CoreBluetooth.framework` to the **Frameworks, Libraries, and Embedded Content** section of the target settings.
6. Update the `Info.plist` with the following usage strings:

   - `NSBluetoothAlwaysUsageDescription`
   - `NSBluetoothPeripheralUsageDescription`
   - `NSLocationWhenInUseUsageDescription` (required on iOS 13+ to scan for BLE devices)

   Provide human-readable justifications for each key.
7. Select an appropriate development team and bundle identifier.
8. Under **Signing & Capabilities**, add the **Background Modes** capability and enable `Uses Bluetooth LE accessories`.

## Running on device

1. Connect two or more devices running iOS 12+ (Bluetooth is unavailable in the simulator).
2. Install and run the app on each device.
3. Complete the registration flow to set a display name.
4. Use one device to create or join a room, optionally setting a password.
5. Use the toolbar's **Broadcast** button to start advertising your presence; other devices will pick you up under the "Nearby" section and the shared service characteristic will be used to exchange messages.

## Notes

- This sample uses JSON encoding over a single characteristic to keep Bluetooth packets small. For production usage, consider chunking large messages and implementing acknowledgements.
- The password store is intentionally simple and backed by `UserDefaults`. Replace with the Keychain APIs for stronger security if you graduate this prototype to a production app.
- Bluetooth operations must be tested on hardware. Simulators do not provide Bluetooth capabilities.
